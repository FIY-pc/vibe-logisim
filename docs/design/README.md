# 工作区界面基础

电路、资料、仿真与对话共同组成工作区。界面帮助用户定位对象、完成操作和判断结果，不用说明文字补偿含糊的操作，也不靠缩小文字塞下更多信息。

统一控件与样式解决一致性，不证明现有工作区结构合理。区域的出现、强调和空间分配应服务于正在进行的任务；阅读资料、编辑电路和检查结果可以有不同安排。反复局部调整仍未改善使用时，应比较不同的组织方式，而不是继续增加视觉规则。成熟组件的价值在于承接通用问题；任务是否更容易完成，需要在实际操作中判断。

## 一个控件入口

普通按钮、图标按钮、输入框、列表操作行和文字从 `apps/workbench/src/design/ui.tsx` 导入。这个入口使用 Radix Themes 实现，保留它的交互、状态和主题，限定产品实际使用的尺度。业务视图不传数字字号、控件尺寸或任意主题色；主要操作用默认强调色，次要操作用灰色，危险操作用红色。

| 用途 | 统一尺度 |
| --- | --- |
| 按钮、图标按钮、单行字段 | 高32px，文字14/20px，图标16px |
| `ActionRow`，含名称和描述的列表项 | 最小高32px，允许内容换行；内边距8px × 12px |
| `Text`，正文、标签、操作名称 | 14/20px；长段落可用24px行高 |
| `Text kind="meta"`，时间、快捷键等辅助内容 | 12/16px |
| `Heading`，内容分组 | 16/24px |
| `Heading kind="dialog"`，弹窗标题 | 20/28px |

字号与点击区域分别处理：辅助信息较小，不意味着相邻按钮也缩小。工具栏的安静按钮与主要按钮占位相同。Themes 的 ghost 控件原本采用负外边距与文字对齐；`design/controls.css` 在唯一适配处将它们变成工作区需要的固定占位，页面不再重复调整。

Radix 的布局、弹层、菜单、页签、表格等通过其公开接口组合。共享 Menu、Select、Dialog 和命令列表负责产品交互边界。电路画布、波形、树的层级与选择等领域内容继续使用专属实现，不把领域内容塞进通用按钮外观。

## 一个样式入口

只有 `main.tsx` 引入 `design/foundations.css`，各业务组件不再导入样式。样式层顺序固定，开发热更新和生产打包不会因为组件导入顺序改变外观：

1. `reset`：浏览器基础和领域原生元素的默认行为。
2. `theme`：Radix Themes 的完整主题与控件样式。
3. `layout`：工作区及各模块的排列、宽度、滚动、显隐和领域绘制。
4. `controls`：设计入口的统一控件占位与列表行规则。

字体、语义色和必要的产品尺寸集中在 `design/tokens.css`，取自 Themes 的字体、颜色、间距、圆角与阴影。页面不得再定义另一套字号或调色板；电路运行值和代码语法高亮保留各自领域颜色。新增样式先判断属于布局还是控件：布局留在所属模块；控件变化应在统一入口解决，让所有使用处一起生效。

## 完整组件与状态

[组件选型](components.md)记录大构件的选择和接入边界。分栏使用 react-resizable-panels；XML编辑与历史对照共用CodeMirror；长对话使用React Virtuoso；文件树使用Headless Tree；搜索使用cmdk；课堂页签与表格使用Themes；提示定位使用Floating UI。

资料阅读使用完整Mozilla PDF.js Viewer，应用负责工程文件、引用与阅读位置的连接。普通窗口可并排，窄窗口切换区域或使用抽屉；切换区域不能丢失草稿、阅读位置和正在进行的工作。长内容有明确滚动区，不能靠压缩正文满足外框尺寸。

同级入口用同一层级表达。账号、额度等低频信息放在设置中。设置先显示常用字段，其余放在高级设置；错误靠近相关操作，失败后保持已填内容。需要决定时使用AlertDialog，普通设置和编辑使用Dialog；焦点、Escape和模态边界交给库。

## 实际检查

通用控件改变后，检查工作区、完整设置、搜索、属性、资料和课堂入口，包括普通窗口、短窗口、长内容、键盘选择与关闭、错误与忙状态、弹窗中的下拉菜单。类型检查约束控件入口；浏览器尺寸和实屏检查确认实际结果。jsdom通过不能代替视觉检查，浏览器检查也不代表已验证Windows原生WebView。
