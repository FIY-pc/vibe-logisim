# Vibe Logisim v0.3.3

这一版只改 AI 的「整理电路」（`arrange_candidate`）：整理后除了画法，其余都保持不变；连线也比以前直。解压替换旧版即可，AI 接口设置和会话记录保存在用户目录，不受影响。v0.3.2 会在应用里提示这次更新。

## 下载

| 系统 | 文件 |
| --- | --- |
| Windows 10/11 x64 | `vibe-logisim-0.3.3-win32-x64.zip`，解压后双击 `vibe-logisim.exe` |
| Linux x64 | `vibe-logisim-0.3.3-linux-x64.tar.gz`，解压后运行 `./vibe-logisim` |

每个压缩包旁边有 `.sha256` 校验文件。首次运行 Windows 可能提示“未知发布者”，选“更多信息 → 仍要运行”。

## 整理电路只改画法

以前用课程框架做关卡时，AI 整理完电路，往往还要手工修补几处。这一版修好了这些问题：

- 面板上的探针如果接进了主体，整理后连线不再丢失。以前这些线会被悄悄断开，等价检查也发现不了。
- 带自定义外观的子电路，整理后能正常打开，使用它的电路里端口位置不变。以前会报 “Appearance element circ-port not found”，或者端口移位。
- 用默认外观的子电路，同一朝向的引脚保持原来的顺序，使用它的电路里端口不会对调。
- 面板上的导线不再被误删。例如按钮的短引线接在一根导线的端点上，Logisim 载入时会把两段合成一根，以前这种导线会被当成已拆掉的旧线删掉。
- 文件里只改被整理的那个电路，其余电路逐字节不变，检出后不需要再恢复。
- 面板识别：整页都是面板、主体还是空的电路，整页保持不动；辅助电路逻辑上方的一列接口引脚，不再被当成面板冻结。

交付整理结果前，除了原有的逐端口连通性核对，还会核对两件事：别的电路看到的子电路实例（端口位置和对应的引脚）是否不变；目标电路以外的内容是否一个字节都没改。任何一项不符就不交付，并报告原因。

## 连线更直

- 相邻两列之间，一个元件的输出接另一个元件的输入时，两个元件会尽量对齐，让这根线成为一条水平直线。以前按相邻端口的平均位置摆放，这类线大多要折两次。
- 元件锚点落在网格上，对齐的端口真正等高。以前有的门会偏开半格（5 px），看着对齐的线其实折了两下。
- 同一列里有空隙时，元件会尽量和邻列元件顶边对齐，或者移到能让一根线变直的位置；引脚也参与，但不改变引脚顺序。
- 单周期 CPU 这类没有流水级的电路：按信号深度分列时，没有上游的元件会全挤在最左边，拉出很长的线。现在只要能缩短连线，元件会右移到它所喂部件的前一列。有两种移法，各画一遍，比较交叉、拐弯、线长和 Tunnel 数，保留较好的一张。
- 多路选择器、多输入门的输入端口只相隔 10 px，以前常被先布的线挡住，只能退回 Tunnel。现在布不通的线会优先重布一次。在课程框架原件和一份完成全部关卡的课程工程上，已经没有因布不通而退回 Tunnel 的端口。

## 已验证

- 新增原生测试：整理前后逐项核对探针连线、自定义外观与默认外观的子电路实例、载入时合并的导线、目标电路以外的字节；另有对照用例，证明默认外观的端口确实按引脚位置排列。两条门电路链整理后每段都是水平直线，元件在网格上，输出引脚顺序和网络不变。
- 课程框架原件和一份完成全部关卡的课程工程里的所有电路都能整理：连通性、子电路实例、目标电路以外的字节全部核对通过。
- 安装包由 CI 的 bundle 工作流打包，在真实 Windows 与 Linux 上冒烟通过后才上传到本 Release。

## 已知限制

- 整理后的图仍比手画的宽：电路按信号深度分列，单周期 CPU 会有十几列，每列只有几个元件。手画时常见的“主数据通路一行、控制器在上、PC 逻辑在下”这种分块，还做不到。
- 课程面板和主体之间留白很小（不到 40 px）时，面板可能识别不出来，整页（包括面板上的显示件和引脚）会被当成主体重排。连通性不变，但面板会乱。遇到时可以让 AI 传 `panelBelowY` 指定分界，或把面板元件列进 `pinnedComponentIds`。
- 其余同 v0.3.2：新版本提示只负责提示，仍需手动下载、解压替换；Windows 上的“信号仍然断开”尚未复现；自定义接口只支持 Responses API；代理只支持 HTTP 代理；从课程模板一键补成五级流水线 CPU 还不稳定；macOS 暂无安装包。
