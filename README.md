# Vibe Logisim

**和 AI 一起搭电路、跑仿真、找问题。**

Vibe Logisim 是一个支持 AI 协作的数字电路工作台。你可以自己画图，也可以把需求和资料交给内置 AI，让它实现电路、解释原理、排查错误，再和你一起把结果改好。

电路编辑、资料阅读、AI 对话和仿真在同一个窗口里完成。成果保存在你自己的文件夹中，是可以继续编辑和运行的 `.circ` 文件。

[下载 Windows / Linux 版](https://github.com/FIY-pc/vibe-logisim/releases) · [反馈问题](https://github.com/FIY-pc/vibe-logisim/issues/new/choose) · [参与开发](docs/development.md)

## 用它做什么

**构建电路。** 从一个全加器、计数器到由多个子电路组成的数据通路，可以手工放置元件、连线、修改属性，也可以用自然语言让 AI 实现。已有工程可以直接打开继续做，不必从空白开始。

**运行与调试。** 切换输入、推进时钟、观察信号，用实际结果判断电路行为。选中相关部分，让 AI 解释连接关系，或结合测试输入查找错误。遇到跨线和隧道，可以追踪信号来源、使用位置及总线位段。

**整理与理解。** 让 AI 按功能和数据流组织复杂图面，保留指定面板与接口；再根据你的阅读习惯调整。图面、连接和仿真结果都可以用来讨论问题，你也能随时接手编辑。

**在工程旁边阅读资料。** 把需求文档、参考资料和组件库放进工作文件夹，在工作台里查看、引用资料并继续讨论。AI 修改后可以查看改动、核对或撤销，不需要在聊天窗口和电路软件之间反复搬运文件。

## 下载与启动

到 [Releases](https://github.com/FIY-pc/vibe-logisim/releases) 下载对应系统的安装包。内置运行时、Python 和 Java 随包提供，Codex 首次使用时自动下载。

| 系统 | 下载文件 | 启动方式 |
| --- | --- | --- |
| Windows 10/11 x64 | `vibe-logisim-<版本>-win32-x64-setup.exe` | 安装后从开始菜单打开 Vibe Logisim；未签名程序可能显示“未知发布者”提示 |
| Linux x64 | `vibe-logisim-<版本>-linux-x64.tar.xz` | 运行 `./vibe-logisim`；需要 GTK3 桌面；Codex 与内置命令执行需要 systemd 用户会话 |

macOS 暂未提供安装包。**人工编辑和仿真无需连接 AI。** AI 功能使用你自己的 API 接口及相应额度；也可以通过 Codex 运行时登录 ChatGPT。

## 开始一个电路任务

1. **打开文件夹。** 放入已有的 `.circ`、组件库和参考资料，或在工作台中新建电路。已有工程建议保持原目录结构，避免组件库的相对路径失效。
2. **自己编辑，或连接 AI。** 手工操作可以直接开始。要使用 AI，打开右栏“AI 设置”添加模型服务，选择预设或填写接口、密钥和模型。内置运行时直接使用 API；也可以从“模型服务”进入 ChatGPT 登录。
3. **描述目标，边运行边完善。** 告诉 AI 想做什么、哪些结构需要保留、期望的输入输出是什么。它会读写工作文件夹中的工程；你可以查看改动、运行验证，再提出下一步调整。

可以从这些小任务开始：

> 新建一个一位全加器，标出输入与输出，验证它的真值表，并解释进位是怎样产生的。

> 解释选中部分的作用，沿着输出信号找到来源。我输入 A=1、B=0 时，输出与预期不符，请检查原因。

> 按文件夹里的要求补全当前电路，保留现有接口。将输入、计算和输出区域组织清楚，验证关键功能，最后说明怎样运行。

复杂任务应提供实际依赖、测试输入和预期结果。模型能力会影响实现和调试效果；对于较大的工程，建议使用推理、工具调用和图像理解能力较强的模型，并在自己的使用环境中核对最终结果。

常用操作：`A` 添加元件，拖动端口连线，`W` 从空白处布线；松手即可落下一段，之后从线头继续。`P` 操作输入，`Ctrl+T` 启停仿真，`Ctrl+Z` 撤销。`Ctrl+点击` 隧道、端口或导线可在当前子电路内追踪信号，`Alt+←` 返回上个位置。

## 电路与 AI 接口的兼容性

支持 **Logisim-ITA 2.16** 与 **HUST 2020 版**的 `.circ` 电路，可在对应版本的 Logisim 中继续使用。打开已有工程时需保留所用的组件库。

内置运行时支持流式 **Chat Completions、Responses 和 Anthropic Messages**；Codex 运行时仍需要 Responses API。接口未提供模型列表时，可以手动填写模型名。密钥保存在本机；图片输入需在高级设置中按模型能力开启。连接检测只验证基本响应，不代表工具或图片能力已经通过验证。

会话保留原来的运行时。可以用另一运行时新建对话，已有对话仍可从列表中恢复。新对话默认运行时单独设置，不改变当前对话。内置模型服务可以并存，新增服务不会覆盖旧会话的连接。内置运行时支持文件读写、电路工具、流式输出、停止和追加意见；Linux 支持隔离命令执行，Windows 暂只提供文件与电路工具。

应用读取系统 HTTP 代理或 `HTTPS_PROXY`，AI 设置中可以查看检测结果。调整代理后点击“重新连接”。纯 SOCKS 地址不支持，可使用代理软件的 HTTP 或混合端口。

## 常见问题与反馈

| 遇到的问题 | 可以怎么处理 |
| --- | --- |
| 电路提示缺少库 | 保持原目录结构，确认 `cs3410.jar`、`riscv-probe.jar` 等实际依赖齐全 |
| AI 接口连接失败 | 在 AI 设置中重新检测；检查地址、模型名、Responses 支持和代理状态 |
| 长任务中途报错 | 查看文件夹里已保存的电路和工作记录后继续；新建对话时，说明已完成内容与待办 |

遇到问题可通过右上角“…”→“反馈问题…”保存诊断包、复制摘要并打开 [GitHub Issues](https://github.com/FIY-pc/vibe-logisim/issues/new/choose)。诊断包不包含 API 密钥、登录信息或对话全文；当前电路默认不附带。公开提交前请查看预览，检查文件名、标签和附件中的个人信息。

应用会检查新版本并提示，不会自动下载安装；可在“…”菜单关闭“自动检查更新”。各版本的变化见 [发布说明](https://github.com/FIY-pc/vibe-logisim/releases)。

## 从源码运行

需要 Node.js 22+、Python 3.11+、JDK 17+；内置运行时无需 `codex`；选择 Codex 运行时才需要本机可用的 `codex` 命令。按 [开发说明](docs/development.md) 放好两个 Logisim 运行文件后：

```sh
npm --prefix apps/desktop ci
apps/desktop/run
```
