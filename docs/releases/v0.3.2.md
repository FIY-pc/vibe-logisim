# Vibe Logisim v0.3.2

v0.3.1 之后的版本，补上两件事：遇到问题时一键备好反馈材料；有新版本时在应用里提示。解压替换旧版即可，AI 接口设置和会话记录保存在用户目录，不受影响。

之前的版本不会检查更新，从这一版起才会在有新版本时提示。

## 下载

| 系统 | 文件 |
| --- | --- |
| Windows 10/11 x64 | `vibe-logisim-0.3.2-win32-x64.zip`，解压后双击 `vibe-logisim.exe` |
| Linux x64 | `vibe-logisim-0.3.2-linux-x64.tar.gz`，解压后运行 `./vibe-logisim` |

每个压缩包旁边有 `.sha256` 校验文件。首次运行 Windows 可能提示“未知发布者”，选“更多信息 → 仍要运行”。

## 反馈问题

右上角新增「…」菜单，点「反馈问题…」（AI 回答失败或连接失败时，AI 面板的提示卡上也有「反馈这个问题」）。对话框里先预览要发出去的内容，再选：

1. **保存诊断包…**：生成一个 zip（默认存到「下载」文件夹），拖进 Issue 的「诊断包与截图」一栏；
2. **复制摘要**：粘贴到 Issue 的「诊断摘要」一栏；
3. **打开 GitHub 反馈页**：打开已填好版本、系统和连接方式的「问题反馈」表单，同时把摘要复制好。

诊断包里有：版本、系统、Java 版本、AI 连接方式和网络方式、路径特征（长度、层级、是否含中文或空格、是否在 OneDrive 或网络位置，不含路径本身）、最近失败的电路工具调用及其参数、应用日志。没有：API 密钥、对话内容、ChatGPT 登录信息和你的其他文件。当前电路默认不附，勾选后才附上。

Issue 是公开的，任何人都能看到。写进日志和诊断包的内容会先替换掉 API 密钥、用户目录、用户名、计算机名、工作区位置和学号；诊断包生成后还会再查一遍，发现漏掉的密钥、用户目录或学号就拒绝保存。文件名或元件标签里仍可能有你的名字，发之前在对话框里看一眼预览。

## 日志写到文件

界面、AI 引擎和电路服务的日志现在写到用户目录，单个文件 2 MB，保留 3 个：Windows 在 `%APPDATA%\vibe-logisim\logs`，Linux 在 `~/.config/vibe-logisim/logs`。「…」→「打开日志文件夹」可以直接打开。之前的版本日志只输出到终端，出了问题事后查不到。

## 新版本提示

启动几秒后访问一次 GitHub，查询有没有新版本（包括预发布版，6 小时内最多一次）。有就在顶部提示，可以「查看下载」或「忽略此版本」。只提示，不下载、不安装任何东西，也不发送个人信息。

- 在「…」菜单里取消「自动检查更新」，之后启动时不再访问 GitHub；「立即检查更新」随时可用。
- 设置环境变量 `VIBE_LOGISIM_NO_UPDATE_CHECK=1` 可以完全关闭。
- 网络不通时不打扰，下次启动再查。

## 已验证

- 新增单元测试 25 项：日志脱敏与滚动、诊断包内容与生成后的检查、版本比较与缓存、失败工具调用的记录，所在文件都已加入 CI 的 Windows 单元测试列表。
- 真实 Electron 端到端：新版本提示出现；忽略后重启不再出现；关闭自动检查后重启不再访问 GitHub；手动检查；日志写入文件；诊断包预览与保存；摘要复制；反馈页链接；AI 引擎启动失败时出现「反馈这个问题」。
- Windows 与 Linux 安装包的冒烟测试各导出一次诊断包并检查内容。Linux 安装包用真实接口跑两轮模型回合后导出，诊断包的每个文件和日志文件里都找不到密钥。
- 安装包由 CI 的 bundle 工作流打包，在真实 Windows 与 Linux 上冒烟通过后才上传到本 Release。

## 已知限制

- 新版本提示只负责提示，仍需手动下载、解压替换。
- Windows 上的“信号仍然断开”尚未复现；再遇到时请用「反馈这个问题」导出诊断包附到 Issue。
- 其余同 v0.3.1：自定义接口只支持 Responses API；代理只支持 HTTP 代理；从课程模板一键补成五级流水线 CPU 还不稳定；整理器的行对齐和等距通道还不如手画；macOS 暂无安装包。
