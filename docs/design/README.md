# 工作区界面基础

电路、资料、仿真与对话需要共同工作。界面优先帮助用户定位对象、完成操作和判断结果；不以增加说明文字补偿含糊的操作或布局。

## 通用组件

通用控件使用 [Radix Themes](https://www.radix-ui.com/themes/docs/overview/getting-started)。Theme 放在应用根部，组件直接使用其公开属性。字体、颜色、间距、圆角和状态从同一套主题取得；领域视图通过语义变量使用这些尺度。

- 正文与普通控件以14px为基准；12px用于必要的辅助信息，不能靠缩小文字容纳本可移走的低频内容。
- 强调色用于当前选择和主要操作；危险、警告和禁用有独立语义。电路的仿真颜色继续由运行时决定。
- 表单先给常用字段，其余放在明确的高级设置中；错误显示在相关操作处。提交时保持已填内容，异步失败允许继续修改。
- 需要用户作决定的操作使用 AlertDialog；常规设置和编辑使用 Dialog。焦点、Escape、模态边界和控件键盘行为交给成熟组件；应用仅处理异步提交和返回工作区的焦点。
- 同级入口用同一层级表达。账号状态、额度说明等低频信息留在设置，高频输入区保持简洁。

应用全局样式在 `workbench` CSS layer 中，Radix Themes 的样式优先。不要为新组件添加逐项覆盖来重建其外观；先用组件属性与主题。领域布局的 CSS 仍可使用，但不应改写通用控件内部结构。

## 工作区与大组件

先调查完整组件，再决定自定义范围。评估对象包括交互、性能、无障碍、离线资源、打包和真实 WebView，而不只是截图。

[组件选型](components.md)记录各大构件的选择和接入边界。分栏使用 react-resizable-panels；XML 编辑与历史对照共用 CodeMirror，保留草稿和显式应用。对话虚拟化、文件树与课堂表格列为后续候选，不与本轮已完成的替换混淆。

已采用的完整资料阅读器为 Mozilla PDF.js Viewer；应用负责工程文件、引用与阅读位置的连接。PDF 页码、搜索、选择和缩放由 Viewer 管理。电路渲染、编辑身份与仿真语义是领域边界，替换相关框架时必须保留这些行为。

尺寸按可用空间判断：普通窗口可并排，窄窗口切换区域或使用抽屉；打开资料、切换页面、收起侧栏不能丢失草稿、阅读位置或正在进行的工作。长内容有明确滚动区，不能靠压缩正文高度来满足外框尺寸。

## 如何验证

改通用组件时，在实际 Desktop 打开完整路径：普通窗口与短窗口、空状态与长内容、键盘选择和关闭、错误与忙状态、弹窗内的下拉菜单，以及关闭后的焦点。自动化检查保留这些行为的回归，但 jsdom 不能证明尺寸和视觉可用。

验证 AI 功能时使用产品自己的运行时；将界面结果、工具结果和真实模型结果分别说明。一个简单任务通过不能代表大型电路的稳定交付能力。
