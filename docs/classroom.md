# 课堂与教师端

课堂服务是独立部署的 Node.js 24 服务，数据存储在 SQLite 中。学生和教师使用同一个工作台的“课堂”入口登录；原有电路编辑与仿真无需登录。服务不读取客户端磁盘，只接收学生明确共享的快照。

## 启动服务

在仓库根目录运行（PowerShell）：

```powershell
$env:CLASSROOM_TEACHER_CODE = '设置一个仅发给教师的随机邀请码'
npm run classroom
```

默认监听 `http://127.0.0.1:8810`，数据库位于 `.classroom-data/classroom.sqlite`，不进入 Git。教师注册需要上述邀请码；学生注册需要姓名和学号。密码至少 10 个字符，服务保存 scrypt 哈希；登录令牌在服务器只保存哈希，12 小时过期，可主动退出。

教师注册后创建课堂，填写任务、评价标准和人数上限，取得课堂码。学生填写同一服务地址，注册后使用课堂码加入。课堂码泄露时，教师可点击“更新课堂码”，旧码立即失效，已加入的学生和历史提交保留。教师也可以关闭课堂，此后不能加入或提交；重新开放后恢复。

多台电脑连接时设置 `CLASSROOM_HOST=0.0.0.0`，并让客户端填写教师服务器的实际地址。跨网络部署应使用 HTTPS 反向代理；把浏览器界面的实际来源加入 `CLASSROOM_ORIGINS`（英文逗号分隔）。默认允许开发页面 `http://127.0.0.1:5173`、`http://localhost:5173` 和 Tauri 的本地来源。

| 环境变量 | 含义 |
| --- | --- |
| `CLASSROOM_HOST` / `CLASSROOM_PORT` | 监听地址 / 端口，默认 `127.0.0.1` / `8810` |
| `CLASSROOM_DATABASE` | SQLite 路径 |
| `CLASSROOM_TEACHER_CODE` | 教师注册邀请码；未设置时禁止注册教师 |
| `CLASSROOM_ORIGINS` | 允许访问服务的页面来源；设置后替换默认列表 |
| `CLASSROOM_AI_BASE_URL` | Chat Completions 兼容接口前缀，例如 `https://provider.example/v1` |
| `CLASSROOM_AI_API_KEY` | 服务端 AI 密钥 |
| `CLASSROOM_AI_MODEL` | 分析使用的模型 |

AI 三个变量必须一起配置；重启服务后生效。密钥不返回客户端，也不写进分析报告。没有配置 AI 时，账号、课堂和审阅功能仍可使用。

## 学生共享

1. 打开工作文件夹和电路，在课堂入口中选中课堂。
2. 填写自报进度和说明，选择是否共享当前 AI 对话。
3. 点击“预览将共享的内容”，检查电路图、XML 和每条交互记录。
4. 点击“共享进度”或“提交电路”。预览本身不会上传。

可以选择每 30 秒共享变化，关闭课堂窗口后仍继续；标题栏会显示“共享中”。绑定的是预览时的文档、文件夹与对话，切换文件夹或对话会暂停，避免把其他任务发到课堂；AI 回合正在运行时等待结束再共享。停止按钮、退出课堂账号或退出应用会停止自动共享；重启不会自动恢复共享。“提交电路”会停止自动共享。

每个快照保留电路 XML、主电路 PNG、修订、元件与导线数量、自报进度、说明，以及选中的当前对话问答与工具结果。不上传模型配置、API 密钥、附件原文件、绝对路径元数据或其他对话。学生自己写入问答和电路中的内容会按预览共享，需自行检查。

单次请求上限 4 MB，XML 上限 2 MB、PNG 上限 1 MB、交互最多 1000 条且每条最多 20000 字；超限会明确提示。当前版本不打包第三方元件库，教师预览使用学生端产生的图像，XML 保留原工程引用。

## 教师审阅和 AI 分析

教师仅能查看自己创建的课堂。学生仅能看到自己在课堂中的提交；课堂列表、提交历史和分析接口都由服务器检查角色及课堂归属。教师审阅为只读，不修改学生电路。

教师看板每 15 秒刷新学生状态，显示自报进度、最近共享时间、元件/导线数量、提问数和工具错误数。选择学生后可查看最近 50 次提交、图面、XML 和问答。

点击“生成分析报告”可以分析全班或当前学生，也可以提出具体教学问题。AI 接收任务、评价标准和授权范围内的最新提交，报告保存模型、时间、覆盖人数和提交证据编号。每位学生都有概要，详细文本总预算 100000 字符，单人最多最近 40 条交互（每条取前 2000 字符）、XML 前 8000 字符；截断与超出预算的记录在提示词中明确标记，可选择学生单独分析。

进度和图像由客户端提供，服务没有运行学生电路，不能视为考试防作弊系统或自动正确性判分。AI 被要求区分自报信息、证据与推测，不能把未共享解释为未学习，也不能仅凭 AI 使用频次认定作弊。

## 数据与开发

账号、成员、不可变提交快照和报告持久化到 SQLite，开启外键和 WAL。备份应在停止服务后复制数据库，或使用 SQLite 在线备份工具，不能只复制运行中的主文件而遗漏 WAL。当前版本不提供找回密码、批量导入、学校 SSO 或自动评分；课堂历史由部署方按课程留存政策管理。

```sh
npm run test:classroom
npm run test:ui
npm run check
```

课堂测试使用真实本地 HTTP 服务、临时 SQLite 和模拟模型接口，覆盖账号、角色、课堂隔离、容量、幂等提交、持久化和 AI 证据范围。UI 测试验证共享预览不上传、敏感配置过滤、教师审阅与分析报告。

设计参考 [AES](https://github.com/pixelnova20/aes) 的 `courseworks` 模块（参考提交 `e6a5634d5d70039c9582ef04901a5bcc0915ce05`）：课堂邀请码、按教师及课堂校验访问、只读审阅和证据驱动分析。本实现使用独立账号与存储，不连接 AES 生产系统，也未复制其源码。
