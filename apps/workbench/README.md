# workbench

The window. React 19 + Zustand, one `Workbench` per mount (`app/createWorkbench.ts`): eight stores, four action groups, one host subscription. Every mutation of circuit state goes to the host; the window keeps only view state (selection, tool, viewport, open panels, drafts) and the last snapshot it was given.

## Owns

- `app/`: composition and lifecycle. `createWorkbench` builds `Stores{notices, settings, shell, conversation, documents, files, editor, simulation}` and `Actions{workspace, editor, simulation, navigation}`; `start.ts` subscribes; `router.ts` applies host events (`simulation`, `resync`, `warning`, connection loss); `keyboard.ts` the shortcut dispatcher; `view.ts` the `View{doc, circuit, instance, scope}` every component reads (`instance`: the subcircuit instance path shown, empty for the circuit itself); `provider.tsx` the React context; `hooks.ts` selectors; `reaction.ts` store-to-store reactions.
- `shared/`: `transport.ts` (`command(request)`: Tauri `invoke("command")` on desktop, `POST /api/command` in the browser; `openPath`/`savePath` file dialogs), `events.ts` (`subscribeEvents`: the page's Tauri `events` channel or SSE), `host-error.ts`, `notices.ts`, `settings.ts`, `shortcuts.ts` (the key table, user-editable), small controls (`DecisionDialog`, `IconButton`, `PropertyField`, `TextPrompt`, `Select` — the only drop-down list, `Checkbox`, `useAutoSize` for growing text areas). Every layer is drawn by the app, never by the platform or its theme: `Menu`/`MenuItem` (button menus, the "···" ones included) and `ContextMenu` (right-click) on Radix menus, `Select` and `Checkbox` on Radix, `Dialog.tsx` (`useModal`: focus starts on `data-autofocus` or the dialog and returns to the opener; `DialogClose`), `layer.ts` (portal container inside the open dialog, focus return), and `Tooltips` — one hint layer for `data-tip` (`tip(text, shortcut)`, `fullText(text)` for labels cut short); native `title` is not used. Commands that open a dialog or a file picker end with "…", commands that act at once do not.
- `shell/`: frame and chrome: `WorkspaceLayout`, `Titlebar`, `Rail` (left tool rail), `Aside` (right column: chat, files, inspector…), `Notices`, `DecisionRegion` (blocking questions), `Feedback*`, `ShortcutSettings*`, `store.ts` (which panels are open, pending host calls).
- `workspace/`: the folder and open files: `documents.ts` (open documents, active id, workspace refresh), `filesStore.ts` + `Files.tsx` (folder tree, file history with undo, imports), `FilePreview` (PDF, images, text), `ProjectInfo` (summary, export), `Welcome`, `FolderPrompt`, `NewFilePrompt`, `SourceNotices` (file changed on disk / missing), `actions.ts`.
- `editor/`: the canvas and editing. The window composes the editor picture itself (`docs/rendering.md`): `symbols.ts` (the recorded pictures of the kinds of components, cached per document by library, name and attributes; `useSymbols` asks the host's `symbols` only for the kinds the document has not drawn yet; the width-conflict wires come with the edit, undo and redo answers (`DocumentChange.widthErrors`, kept per circuit by `recordWidthErrors`), and a circuit shown before any answer reported them (just opened or re-read) gets them from one `symbols`; `keepSymbols`, which `actions.ts`'s `watchSymbols` calls with the open documents, forgets closed ones), `paint.ts` (`program` compiles a picture's ops, `buildScene` lays out parts, wires, junctions, bounds and ports, `paintFrame` paints one frame, strokes placed on the pixels Java2D puts them; during a run it paints the run's wires, junctions and components instead, `Frame.live`), `CanvasPicture.tsx` (the `<canvas>` under the SVG layer, painted at the next animation frame), `geometry.ts` (hit testing, box selection and fitting from the recorded bounds), `useConnections.ts` (`connections`: only the nets of the selected components and wires and of a traced click, each seed read once per revision, only while connections or a traced signal are shown), `usePlacementQueue.ts` (placement clicks committed in order, each ghost kept where it was clicked until the document has it), `useMovePreview.ts` (`movePreview` while dragging: the wires Logisim's move gesture would take out and add, one request at a time, which the drag never waits for). `Canvas.tsx` is the interaction (tools, pointer and keys, dragging, wiring, commits, marks on the SVG layer) and assembles the frame it paints. Around it: `store.ts` (tool, selection, viewport, placement), `actions.ts` (edit, undo, redo, move, delete, attributes through host ops), `usePlacement`, `EditorToolbar`, `Inspector` + `PlacementInspector` (attributes via `properties`/`template`), `PaletteRegion` (`catalog`), `Connections*`/`connectivity.ts` (signal tracing on the nets read with `connections`; every record carries the document's ids, so a selection and its connections match by id), `CircuitList`/`CircuitActions`/`CircuitPrompts`/`Breadcrumbs`/`navigation.ts` (subcircuit navigation), `FindDialog`, `InterfaceEditor` (subcircuit pins and symbol), `SourceDialog`, `arrange.ts` + `arrange-worker.ts` (`packages/arranger` in a module worker for the user's own "整理" action), `symbol-geometry.ts` (the interface editor's symbol shapes), `componentLabels.ts`.
- `simulation/`: `store.ts` (what the events say: the run, the shown frame's circuit, instance path and clock, components, the picture `paint`, the waveform, the memory page, how the last run ended; plus inputs waiting for their frame by `commandSequence`; `live(state, view)` is whether the canvas shows the run), `actions.ts` (`simulationStart`/`Command`/`Navigate`/`Stop`; `onEvent` is the only writer of run state), `simulation.ts`, `simulationInputs.ts` (poke, input values, buttons), `SimulationControls`/`SimulationDock`/`SimulationTransportRegion`/`SimulationMenuRegion`, `InstanceBar`, `MemoryPanel`, `Waveform`, `Observations` (kept observations), `SimulationAlerts`, `CaptureNotice`.
- `conversation/`: `Chat.tsx` (binding to the folder's conversation, sending, stopping, replaying `agent` events by sequence), `turns.ts` (splits the messages into one segment per question, the summary line of a finished turn), `Turn.tsx` (one turn: live steps, the folded summary, the end line, the files card with undo), `ConversationContent` (markdown, copy, scroll following, conversation picker), `ChatReferences` + `references.ts`/`conversationReferences.ts` (attached files and observations), `ModelPicker`, `ProviderSettings` (services, keys, probe), `store.ts`.
- `history/`: `DocumentHistory` (per-document history list), `HistoryReview` (review of one entry with before/after render and `sourceDiff.ts`), `ChangesRegion`.
- `generated/`: TypeScript copies of the host types. Never edited by hand; `npm run contracts`.
- `src-tauri/`: `main.rs` (creates `Host`, exposes the `command` invoke and the per-page `events` channel, shuts the host down on exit), `installation_check.rs` (bundled runtimes present), `tauri.conf.json`.

## Does not own

Any rule about documents, saving, history, simulation lifetime or AI scope. If the window has to check something to stay correct, that check belongs in the host; the window only displays the host's answer.

## How data flows

- Read: a component calls `useWorkbench()` → store state. Stores are filled from host results (`status`, `read`…) by the action modules; run state only from `simulation` events. The canvas's own reads (`symbols`, and `connections` while connections are shown) stay in its hooks; what `connections` answered is copied to `editor.store` (`canvasObservation`) for the inspector.
- Write: an action builds `{op, ...}` → `command()` → host → the result replaces the relevant store slice. Edit, undo and redo results carry `change` (what changed since the revision they were sent for, only the changed circuits), `selection` and `title`; `documents.applyChange` applies it to the open document, or reads the workspace again when that document is no longer at the change's base revision. The canvas shows the host's revision. A committed wire, delete or move draws its own result (the new wire, the objects hidden or displaced, the move's rerouting from `movePreview`) from the next frame until that revision arrives, and placement ghosts stay where they were clicked; nothing else is predicted (wire repair, merged wires and changed kinds come with the answer). A drag moves the selection with the pointer and sends nothing it waits for; release is one `edit` move, which Logisim's move gesture resolves (an end dropped onto a wire connects). Shift while dragging moves without keeping connections, as in Logisim. Where the move would leave an end unconnected, red dots mark the end's old and new place. A picture or connection read the host refuses as stale (`STALE_REVISION`: another revision exists) re-reads the workspace instead of showing an error; only a refused edit reports it.
- Push: `router.ts` → `simulation` events into `simulation.store` (each subscription, a reloaded page's too, starts with the run's whole state); `resync` → re-read the workspace; `documents` → re-read the workspace (the host read open documents again from their files outside any command of this window); `warning` → notice. `agent` events go to `Chat.tsx`, which owns the sequence gap check: it loads the conversation with `history` when it binds, switches conversation or misses events, replays newer buffered events after it, and otherwise reads the state alone with `status`; AI edits arrive as `document-changed {change}` and go to `documents.applyChange`.
- Shortcuts: `shared/shortcuts.ts` table (1 选择, 2 布线, 3 操作输入, 4 平移, A 元件库, Ctrl+K 时钟, Ctrl+T 一步, Ctrl+Z 撤销, Ctrl+S 保存, Ctrl+, 快捷键) → `app/keyboard.ts` → actions.

## Remaining tasks

1. Done: the toolbar delete button posts `deleteRequest` on the editor store and the canvas commits it as it does the Delete key (`editor/EditorToolbarRegion.tsx`, `editor/Canvas.tsx`).
2. Done: the conversation shows one turn per question as the Codex app does (`conversation/Turn.tsx`, `turns.ts`): while it runs, reasoning, text and tool lines appear as they stream; when it ends, everything before the last text folds into one summary line with the elapsed time, the answer and the files card stay, and a failure or stop ends the turn with one line. The turn record from the runtime carries status, error, elapsed time and the file change, so a reload rebuilds the same view from `status`.
3. Done: the window draws the editor picture itself (`docs/rendering.md`). Panning and zooming repaint at the next animation frame from the cached pictures, with no request and no settle wait; an edit's answer is painted at the next frame after it arrives; showing a circuit costs one `symbols` request for the kinds the document has not seen. `useMovePreview` sends one `movePreview` at a time and, when it returns, the latest offset if the drag moved on; the drag itself never waits for it.
4. Old UI for reference only: `git show HEAD:apps/workbench/src/components/Canvas.tsx` etc. (132 files under `components/ regions/ stores/ lib/ actions/ workbench/` at `HEAD`). Do not port features back without a user asking.
5. Check the window in the desktop web views, not only in Chrome: WebKitGTK (Linux) and WebView2 (Windows). Things the browser preview cannot show: hints on disabled buttons (Chrome sends them no pointer events, so they show none), scrollbar styling, the 140 ms layer fade, and focus returning to a menu's button after its dialog closes.
6. Waveform rows and kept observations name a signal `label [port index]`. The inspector names ports (数据, 地址…) from the observed connections; carry that name in `TraceSignal` and in the observation's signal label (`crates/workbench-host/src/simulation/observations.rs`) so the three read alike.
7. Text fields keep the web view's own context menu (cut, copy, paste, spelling). If WebKitGTK's looks out of place next to the app's menus, give fields an app `ContextMenu` with the same commands.
8. Parts from third-party libraries (`.jar`) keep the runtime's names; built-in libraries and parts are translated in `editor/componentLabels.ts`, keyed by native factory name. Add a part there when the runtime gains one.
9. Done: the window draws the running circuit too (`docs/rendering.md`, 运行中的画面). Each `frame` event carries what changed in the run's picture (wire and junction colors, the ops of changed components, as the runtime recorded them with values shown); `onEvent` lays it over `paint` and the canvas paints it as `Frame.live` while `live(state, view)` holds, so panning and zooming a run send nothing. Kept observations carry the canvas's PNG (`imageData`).
10. Done: edit, undo and redo answers carry each changed circuit's width-conflict points (`DocumentChange.widthErrors`; the host asks the worker's `width-errors` before answering), so an edit is one request and the orange comes with its answer; `useSymbols` asks only when a kind is missing. A circuit first shown without such an answer (open, reload, a re-read workspace) still gets them from one `symbols`.
11. Done: the connections panel and signal tracing read `connections {id, revision, circuit, components, wires, point?}`, which answers only the bit nets of the selected objects and the traced click, in `ConnectionFocus` shape (`crates/logisim-runtime/README.md`, Connections). On the 713-component course page a selection reads 3–72 KB in 2–4 ms on the host instead of the whole page's `observe` (3.6 MB, 140 ms). A selection kept across an edit is read again for the new revision: one small request after the edit's answer, off the picture path.
