## 新发现并修复的问题

| 问题 | 复现与修复 |
|---|---|
| 并发试评绕过评测串行限制 | 两个请求先通过检查、再等待读取请求体，会同时启动评测；上传结束后重新检查并占用评测槽位。覆盖另一个教师试评及学生评测正在运行两种情况。 |
| 同步抛错导致评测槽位永久占用 | 评测函数在返回 Promise 前抛错会跳过旧 finally；统一通过 Promise 调用，异常后释放槽位，后续试评可继续。 |
| 上传期间课堂/关卡状态过期 | 慢上传期间教师修改测试用例或关闭课堂，旧请求仍会被接收；读取请求体后重新校验权限、课堂状态与关卡版本。教师试评也带版本，避免用旧界面的预期值统计新用例。 |
| 多章节成绩单列顺序错乱 | 原矩阵仅按关卡 position 排序，会出现第一、第三、第二、第四关；改为先按章节、再按关卡排序，与目录、成绩单及 AI 证据一致。 |
| 导出成绩单未处理公式型姓名/学号 | 通过实际 UI 注册姓名 `=1+1`、学号 `=2+2` 的学生并生成成绩单，确认旧代码直接导出。现在引用 CSV 字段并对公式前缀、控制字符作文本处理。 |
| 同名子电路被识别成输入引脚 | 名为 Pin 的本地子电路实例被加入用例输入；仅识别实际声明为 `#Wiring` 的库中 Pin 元件，支持不同库 ID。 |
| 评论分页小数触发服务器错误 | 公共评论和后台评论列表传入 `offset=0.5` 时 SQLite 返回错误并变成 HTTP 500；统一验证整数及范围，返回 HTTP 400。 |

CSV 处理面向人工在表格软件中查看，参考
[OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection)，
在带引号的危险字段前加制表符，保留引号转义。没有把姓名限制为只能输入特定字符。
