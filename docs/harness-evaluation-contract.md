# 观察与验证

电路可以加载、图面看起来合理、某次输入产生了输出、输出符合期望，是不同结论。工具返回的事实应保留产生它们的输入与范围，避免把局部观察表述为整个工程已正确。

## 结果归属

| 材料       | 归属                                   |
| ---------- | -------------------------------------- |
| 结构观察   | 文档修订、电路、原生组件与端口位网     |
| 运行采样   | 根电路、实例路径、运行会话及输入动作   |
| 留存观察   | 冻结源版本、明确观察的端口、轨迹和图像 |
| 向量与轨迹 | 源修订、电路、外部依赖和运行时身份     |
| 历史比较   | 两个历史源版本的确切 XML               |

原生位网 ID 只在该次观察中有效，不能直接当作跨版本身份。资料、外部库或运行时改变后，应重新确认对应结果的适用范围。无法取得完整原生覆盖时，应说明局部或不可用。

## 结构与运行

组件属性、端口位宽、连接分区和层级来自 Logisim。几何相交不等于电气连接；没有静态异常也不意味着功能正确。布局移动在写入前核对移动后与原始端口连接分区，不满足连接约束的修改不会进入文档。

输入、时钟和 RAM 状态只属于运行会话，不产生结构修订。轨迹按逻辑步骤和 tick 采样，不是均匀物理时间轴。显示帧可能被合并，轨迹观察与图像刷新独立。

测试向量或时序脚本有明确期望时才能比较结果；没有期望只有观察。未知、电气错误和未稳定状态不能通过普通数值断言。通过只表示给定源版本在已列输入与期望下满足检查，不代表所有输入或全部任务要求。

## 留存与比较

留存观察固定修订、根电路、实例路径、端口和图像，不暂停正在运行的仿真。保存过程拒绝迟到的其他会话结果。波形窗口有界，并显示被丢弃的样本数量。

跨观察比较要求电路身份相同，只比较双方明确共有的被观察端口，不通过标签猜测未记录的状态。历史源比较保留确切 XML；若原外部库已变化，旧版图面可以不可用，源文本仍可查看。

向量与轨迹验证使用独立 Java 进程，不能改变用户的活动仿真。结果绑定产生它的源修订，源改变后不能继续沿用旧结果。通过验证不代表文件已保存，也不会绕过保存冲突。

## 实现与检查入口

- 宿主观察与留存：`crates/workbench-host/src/simulation/observations.rs`。
- Java 运行与原生语义：`crates/logisim-runtime/`。
- 运行、轨迹、观察场景：`scripts/workbench/simulation-scenarios.mts`。
- 历史和依赖场景：`scripts/workbench/history-check.mts`。
- 实例输入与按钮生命周期：`scripts/workbench/simulation-controls-check.mts`。

这些场景使用独立合成电路，校验产品能否保留正确身份和状态。实际工程的期望输出、覆盖范围和独立脚本仍由该工程定义。
