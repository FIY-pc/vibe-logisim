# Vibe Logisim v0.3.1

v0.3.0 之后的修正版本，针对第一批同学反馈的两个问题：AI 打开电路文件时的路径报错说不清楚；「批量连接电路」在个别情况下报“信号仍然断开”却没有线索。解压替换旧版即可，AI 接口设置和会话记录保存在用户目录，不受影响。

## 下载

| 系统 | 文件 |
| --- | --- |
| Windows 10/11 x64 | `vibe-logisim-0.3.1-win32-x64.zip`，解压后双击 `vibe-logisim.exe` |
| Linux x64 | `vibe-logisim-0.3.1-linux-x64.tar.gz`，解压后运行 `./vibe-logisim` |

每个压缩包旁边有 `.sha256` 校验文件。首次运行 Windows 可能提示“未知发布者”，选“更多信息 → 仍要运行”。

## AI 打开电路文件时的路径错误

Linux 上有同学遇到：让 AI 新建一个电路封装后，AI 反复“刷新电路 → 找不到电路定义 → 打开电路 → 文件路径无效”，绕不出来。原因是主机只回了一句“文件路径无效”，AI 不知道该改成什么。现在：

- AI 传绝对路径、但确实指向当前文件夹里的文件时直接接受（AI 的工作目录就是这个文件夹，它很自然会这么写）；Linux 上写成反斜杠的路径，若对应文件存在也接受。
- 其余情况返回带说明的结构化错误：`INVALID_PATH`（绝对路径或含空字符）、`FILE_OUTSIDE_WORKSPACE`（解析到了工作区之外）、`FILE_NOT_FOUND`（工作区里没有这个文件），并附工作区根目录、当前打开的文件、可用的 .circ 列表，以及能推断出来的正确路径（同名文件，或去掉根目录后的相对路径）。
- 工具说明里写清了 `path` 必须是相对工作区根目录的路径。

## 「批量连接电路」报“信号仍然断开”时给出诊断

Windows 上有同学遇到：让 AI 批量连线，布线写回后的校验报“要求连接的信号仍然断开: AND Gate@(…) bit 0”。我们在 Linux 上用两种运行时（仓库自带的 Logisim-ITA 与课程发布的 2020 运行文件）、CRLF 换行、非格点端口、线中途接端口、Tunnel 引线等情形都没有复现。这一版先把校验失败时的现场带出来：失败端口与它本该同网的端口、重载后两边各在哪个网、这次请求的连接里哪些涉及它、为它画了几段线、端口位置上有哪些导线、布线前后的导线数量，以及操作系统、Java 版本与运行时 jar 的摘要；提示语按“根本没有为该连接画线 / 画了线但重载后仍不通 / 出现未要求的短接”三种情况分别给出下一步。再遇到时请把这段报错原文贴到 Issue 里。

## 其他

- 文档中指向开发期内部记录的链接改为纯文本，结论保留在正文里。
- 桌面端 README 的运行示例改用占位路径；画布端到端脚本改由环境变量 `VIBE_COURSE_PACKAGE` 指定课程包目录。

## 已验证

- 新增单元测试：AI 打开电路的六种路径情形（工作区内绝对路径归一化、反斜杠路径、工作区外、不存在、越界链接、其它错误原样透传）；布线后校验失败的五种诊断输出（含“重载结果与写入前一致”的情形）。全部通过，前者已加入 CI 的 Windows 单元测试列表。
- 经真实主进程链路核对，AI 传入的错误路径拿到的是上述结构化错误，不是原始异常文本。
- 安装包由 CI 的 bundle 工作流打包，在真实 Windows 与 Linux 上冒烟通过后才上传到本 Release。

## 已知限制

- Windows 上的“信号仍然断开”尚未复现，本版只提供诊断，不算修好。
- 其余同 v0.3.0：自定义接口只支持 Responses API；代理只支持 HTTP 代理；从课程模板一键补成五级流水线 CPU 还不稳定；macOS 暂无安装包。
