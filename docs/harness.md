# AI 运行时与电路工具

AI 进程连接模型服务、管理会话和调用工具；Rust 宿主管理工程、文档与运行状态。内置运行时和 Codex 共用宿主提供的电路能力，模型仍可直接编辑 XML、读取资料或使用脚本，工具不强制规定解题顺序。

## 入口与契约

| 入口                                                    | 职责                                              |
| ------------------------------------------------------- | ------------------------------------------------- |
| `packages/agent-runtime/src/worker.mts`                 | Node 进程协议、工程绑定、请求调度、事件和工具回调 |
| `packages/agent-runtime/core/`                          | 会话、模型服务、内置与 Codex 运行时               |
| `crates/workbench-host/src/agent.rs`                    | 宿主与 AI 进程的请求、响应及生命周期              |
| `packages/agent-runtime/src/generated/edit-schema.json` | 从 Rust 生成的结构编辑参数                        |
| `packages/agent-runtime/circuit-knowledge/`             | 按需读取的电路和运行时参考                        |

应用命令和编辑类型由 Rust 定义。修改后运行 `npm run contracts`，通过 `npm run check:contracts` 检查生成文件。工具只投影宿主实际支持的操作，不维护另一套电路语义。

## 工作区和写入

每次发送绑定工程、文档、修订和当前电路。准备过程串行协调绑定、资料、工具与会话，过期发送不能落到新切换的电路。停止请求独立于准备队列，仍可及时到达运行中的回合。

电路工具调用宿主编辑路径；源文件保存和冲突处理由同一文档规则管理。通用文件与命令工具在工作副本中运行，电路改动成为可恢复的提案。提案保存原始版本与候选 XML，用户明确应用时检查当前修订；过期提案可读但不能覆盖新稿。一次完整应用对应一个撤销步骤。

选区、资料片段与观察是明确的讨论上下文，文件内容和工具输出按不可信数据处理。资料引用保留文件身份、内容摘要和边界；不是把整个工作文件夹自动装进提示词。

## 会话和模型

会话保留自己的运行时及模型服务绑定。默认值影响新会话，不静默重定向已有会话。有历史的会话切换接收服务时，界面展示上下文转交影响。服务返回的模型列表决定可选项；Models.dev 元数据补充名称和能力，不创造服务可用性。

Codex 工具和指令与原生线程契约绑定。同一契约恢复原线程；契约变化则创建新线程并显式携带有长度上限、标明不可信的文字上下文。该文字交接不重建旧工具结果或运行状态。只有原生确认回合 ID 后交接才完成，失败可重试。

会话流按实际运行事件显示正文、过程、工具和结果。快照携带事件游标，重新连接不会重复拼接同一段文字。修改历史消息、分支、停止和追加意见分别采用运行时支持的语义，不推断已经发生的文件修改被一并撤销。

## 验证

`npm run test:runtime` 使用本地夹具检查绑定、并发、取消、模型偏好、代理、安装下载与提案恢复。`npm run test:native` 检查从本地模型协议到真实 Rust/Java 电路操作的路径。`npm run test:codex` 单独下载锁定 Codex，在临时未登录状态检查原生历史和分支协议，不发送模型回合。

这些检查不证明远端服务质量。电路观察和测试结论的边界见 [观察与验证](harness-evaluation-contract.md)。
