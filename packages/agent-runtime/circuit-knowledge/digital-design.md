# 数字电路：用于选择构建方法的知识

以下是定向调研的简要综合和对本产品的设计建议，不代表已证明某种方法提高所有任务的成功率。教材提供一般原理；课程任务书、实际组件语义和用户决定确定本工程的实现约束。

## 组合电路

布尔表达式、真值表、选择器网络与层次化组件是不同的表示，不必把大电路展平成一个真值表。小规模控制逻辑适合化简；宽数据通路通常先按算术、选择、比较和移位来表达，再处理位宽、符号及端口。选用内建组件还是门级展开，取决于教学任务，不只是等价性。

真值表的无关项是规格允许的自由，不等于未连接或运行中的 X。逻辑等价也不自动意味着无毛刺：若输出作为异步控制或时钟相关信号，必须另外考虑过渡行为。Logisim 的传播演示不能证明物理器件的模拟时序裕量。

来源：[MIT 6.004 组合逻辑](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c4/c4s1/)。

## 时序电路与状态机

先表达需要记住什么，再确定状态更新和输出。同步状态机通常可分解为状态寄存器、下一状态组合逻辑与输出逻辑。Moore 与 Mealy 的输出依赖不同，应明确用户希望输出在什么时刻成立。转移条件应无歧义并覆盖所有允许输入；明确复位和未使用状态编码的处理。

示例：带同步复位和使能的寄存器可以表达为 Q_next = reset ? initial : enable ? D : Q。这只是一个明确了优先级的例子，不能套到异步复位或不同优先级的任务。时序补全还应核对触发沿、使能极性、存储器读写语义；不是“连通后多 tick 几次”。

来源：[MIT 6.004 状态机](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c6/c6s1/)、[时序逻辑](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c5/c5s1/)。

## CPU 和流水线

把数据通路与控制的关系写清楚：每条操作读取什么、产生什么、在哪一阶段可用、何时消费和产生副作用。由依赖与可用时刻推导前递和暂停，再按分支决策位置确定需要冲刷哪些更年轻指令。不要从其他 CPU 照搬停顿周期数。

对每个流水寄存器明确携带的数据与控制、保持条件、清空条件以及同时发生时的优先级。气泡应避免寄存器写回和存储等副作用。具体方案必须服从当前 ISA/课程约定与实际存储器延迟；MIT Beta 的字段和流水行为不能直接当 RISC-V 模板答案。

来源：[MIT 6.004 流水线](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c15/c15s1/)。上述面向本产品的工作组织方式是综合建议。

## 教学层次与构建代价

功能等价不是唯一目标。练习门级加法器时不应以内建加法器替代；构建 CPU 时也不必将已经完成的 RAM 拆成大量基础门。保留可解释、可复用的子模块边界。Nand2Tetris 的 RAM 项目明确推荐部分下层使用内建实现，避免仿真对象爆炸。

来源：[Nand2Tetris Project 3](https://www.nand2tetris.org/project03)。

## 如何用这些知识推进当前任务

只针对当前不确定点补充研究。先用学科知识提出可解释方案，然后在既有工程约束下实现；通过原生读数或有针对性的执行区分错误假设，而不是用自造参考答案确认自己。保留来源与适用条件，尤其是课程简化指令语义、端序、位切片、零寄存器、分支条件和复位约定。
