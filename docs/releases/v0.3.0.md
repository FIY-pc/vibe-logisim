# Vibe Logisim v0.3.0

自 v0.2.0 以来面向同学的第二个公开版本。三件事：连 AI 这一步做扎实、能打开往届同学的旧版文件、AI 整理电路的结果按往届手画的画法来。

## 下载

| 系统 | 文件 |
| --- | --- |
| Windows 10/11 x64 | `vibe-logisim-0.3.0-win32-x64.zip`，解压后双击 `vibe-logisim.exe` |
| Linux x64 | `vibe-logisim-0.3.0-linux-x64.tar.gz`，解压后运行 `./vibe-logisim` |

每个压缩包旁边有 `.sha256` 校验文件。首次运行 Windows 可能提示“未知发布者”，选“更多信息 → 仍要运行”。

## 连接 AI 更省事

AI 设置重做（右栏齿轮，或 AI 面板提示卡上的按钮）：

- 两个并列页签：**ChatGPT 账号** / **自定义接口**。没配置过时直接落在「自定义接口」页；已登录 ChatGPT 或已保存接口时落在对应页签。
- 自定义接口：填好地址和密钥后自动读取接口的模型列表（可搜索、可键盘选择；接口不提供列表时可直接输入）。嵌入、语音、图像等不能对话的模型会从列表里去掉。
- **保存前先检测**：点「保存并连接」会先向接口发一条与实际请求同形状的流式测试请求。密钥无效、地址不对、模型名不存在、接口只支持 chat/completions、限流、服务端错误、超时——都在保存前用中文说清，并保留接口返回的原话。检测失败时可以「跳过检测直接保存」。
- 重新保存不必再输密钥（输入框提示已保存的密钥尾号，留空即沿用）。
- 接口读到的全部模型进入输入框上方的模型选择器，可以直接切换；「思考深度」新增「关闭」档，给不接受推理参数的模型用。可为接口设置模型上下文窗口（默认 256k），长任务不再因为窄窗口反复压缩上下文丢状态。
- AI 面板提示卡同时给出「登录 ChatGPT」和「填写 API 接口」两个入口。
- **读取系统代理**：Clash、v2rayN 等开启「系统代理」后（或设置了 `HTTPS_PROXY` 环境变量），ChatGPT 登录、接口请求和保存前的检测都自动经过该代理。AI 设置右下角显示检测到的代理地址或「直连」，代理设置变化后提示「重新连接」；连不上时的错误提示会说明这次走的是代理还是直连。

已保存的接口设置（provider.toml）无需重新填写，首次打开设置会按旧格式读出。

## 能打开往届的旧版文件

- 用 Logisim **2.7.1** 保存的课设文件（2016–2019 届常见）现在能打开、渲染、仿真。这些文件里的触发器带有新版运行时不认的默认属性，之前要么整份文件打不开，要么被静默丢掉元件；现在按每个电路的元件数逐一核对后放行，凡是会丢元件的情况仍然明确报错，不会给你一张缺零件的图。
- 文件里记录的组件库路径若是作者自己机器上的绝对路径（`cs3410.jar`、`riscv-probe.jar` 常见），现在按文件名在电路文件同目录查找；找不到时说明缺哪个文件、该放在哪里，不再卡死或弹空白错误。

## AI 整理电路按往届手画的画法

「整理电路」（AI 调用的 `arrange_candidate`）重写了：什么距离该用导线、什么距离该用 Tunnel、寄存器怎么排、通道留多宽，这些常数全部来自往届同学手画 CPU 的统计，而不是拍脑袋。整理前后网表逐位等价才写回文件，不等价就不动你的图。

在按 129 份往届手画 CPU 校准的可读性评分上，课程模板骨架（全 Tunnel 的 stage2 / stage5）从 0.47 / 0.30 整理到 0.81 / 0.78，往届手画中位数是 0.79。也就是说它能把乱图、全 Tunnel 图和 AI 生成的图整理到交得出去的水平，但不会比认真手画的同学画得更好——把一份已经画得好的手画图再整理，多半反而变差。

## AI 改图更少出错

- 元件编号按位置生成，别处的改动不再让编号漂移，AI 改一处不用重读整张图。
- ROM/RAM 的内容可以由 AI 直接写入。
- 写回文件时当场检查位宽短接、无法加载、改到目标电路之外，都写进回执，不会留下打不开的文件。
- 用仿真观察信号时，观察点接错或全程未知会被诊断出来，而不是得出「CPU 跑不起来」的结论。

## 已验证

- CI 单元测试（12 个文件、37 项）全部通过：接口探测（模型列表、试连、各类错误分型）、接口配置读写、系统代理解析；布局与判分的 Python 单测另行通过。
- 真实 Electron 端到端（AI 设置）：提示卡入口 → 错误密钥在保存前被拦下且未写盘 → 正确密钥自动列出模型 → 保存后连接成功、模型选择器列出接口模型 → 重开设置不重输密钥再保存 → 停用接口恢复。
- 真实 Electron 端到端（系统代理）：接口放在只有代理才能解析的域名后面，设了代理的实例里模型发现、保存前检测和 AI 子进程的真实回合都经过代理；未设代理的实例页脚显示「直连」，同一接口在保存前失败并提示开启系统代理。
- 打包件（linux-x64，v0.2.1 内部构建）在有、无系统代理两种条件下各跑完两轮真实模型回合（含写回全加器）。
- 整理器回归：11 个固定 case（课程模板、往届手画 CPU、合成测试电路）整理后全部网表等价。
- Windows/Linux 安装包由 CI 的 `bundle` 工作流打包，各自在真实系统上冒烟通过后才上传到本 Release。

## 已知限制

- 自定义接口仍只支持 **Responses API**（Codex 0.15x 已移除 chat 模式）。只提供 `chat/completions` 的接口，保存前检测会明确指出。
- 代理只支持 HTTP 代理（Clash/v2rayN 的 HTTP 或混合端口）；纯 SOCKS 端口会在设置里提示「代理不支持」。带账号密码的代理：保存前检测会报代理要求认证，可「跳过检测直接保存」，AI 引擎本身能用。
- 从课程模板一键补成五级流水线 CPU 还不能稳定成功。AI 更适合讲解、检查、局部修改、小模块构建，以及把画好的图整理干净。
- 整理器的行对齐和等距通道还不如手画，下个版本改。
- macOS 暂无安装包。Windows 上 AI 进程由 Codex 的 workspace-write 沙箱限制（只能写打开的文件夹和应用配置目录）；Linux 上由 systemd 隔离。
