# AI 运行时与电路工具

AI 进程连接模型服务、管理会话和调用工具；Rust 宿主管理工程、文档与运行状态。模型通过工具直接读写打开文件夹里的文件，也可以直接编辑 XML、读取资料或使用脚本，工具不强制规定解题顺序。

## 入口与契约

| 入口                                                            | 职责                                              |
| --------------------------------------------------------------- | ------------------------------------------------- |
| `packages/agent-runtime/src/worker.mts`                         | Node 进程协议、工程绑定、请求调度、事件和工具回调 |
| `packages/agent-runtime/src/{models,conversations,turn,tools}/` | 模型服务、对话、回合与工具                        |
| `crates/workbench-host/src/agent/mod.rs`                        | 宿主与 AI 进程的请求、响应及生命周期              |
| `packages/agent-runtime/src/generated/edit-schema.json`         | 从 Rust 生成的结构编辑参数                        |
| `packages/agent-runtime/circuit-knowledge/`                     | 按需读取的电路和运行时参考                        |

应用命令和编辑类型由 Rust 定义。修改后运行 `npm run contracts`，通过 `npm run check:contracts` 检查生成文件。工具只投影宿主实际支持的操作，不维护另一套电路语义。

## 工作区和写入

每次发送绑定工程、文档、修订和当前电路。准备过程串行协调绑定、资料、工具与会话，过期发送不能落到新切换的电路。停止请求独立于准备队列，仍可及时到达运行中的回合。

电路工具调用宿主编辑路径；源文件保存和冲突处理由同一文档规则管理。文件与命令工具直接作用于打开的文件夹；每个 AI 回合记录一次文件夹检查点，对话中列出改动的文件，用户可以查看并撤销。

选区、资料片段与观察是明确的讨论上下文，文件内容和工具输出按不可信数据处理。资料引用保留文件身份、内容摘要和边界；不是把整个工作文件夹自动装进提示词。

## 会话和模型

模型服务通过用户自己的接口访问，支持 Chat Completions、Responses 和 Anthropic Messages。会话保留自己的模型服务绑定。默认值影响新会话，不静默重定向已有会话。服务返回的模型列表决定可选项；Models.dev 元数据补充名称和能力，不创造服务可用性。

会话流按实际运行事件显示正文、过程、工具和结果。快照携带事件游标，重新连接不会重复拼接同一段文字。停止回合不推断已经发生的文件修改被一并撤销；撤销通过文件夹检查点显式进行。

## 验证

`npm run test:runtime` 使用本地夹具检查代理、资料引用与内置运行时指令。`npm run test:native` 检查真实 Rust/Java 电路操作的路径。

这些检查不证明远端服务质量。电路观察和测试结论的边界见 [观察与验证](harness-evaluation-contract.md)。
