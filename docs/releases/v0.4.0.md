# Vibe Logisim 0.4.0：把完整课设做出来，也让它读得懂

0.4.0 把 AI 构建、图面组织、信号追踪与原生仿真连成了一条可以实际做课设的工作路径：给出需求和初始材料，得到可编辑、可运行的电路，再通过你的反馈继续改好。

## 复杂电路有了阅读顺序

这次重点解决的是图面整体如何组织。电路可以按功能划分区域，沿主数据流安排阶段，把控制支路放在相关模块附近；寄存器阵列保持规则排列，公共 CLK、复位和使能信号尽量保留清楚的干线与支路。输出端靠近来源，减少只为挂一个标签而绕远的长线。

已有课设里的固定面板、接口和指定结构可以作为整理约束。布局工具会核对连接与接口，并检查声明的保护范围；AI 仍可通过直接编辑和脚本完成任务。把“哪些能动、哪些必须保留”告诉它即可。

内置 AI 的交付要求也覆盖了图面：读懂需求、实现功能之后，还应检查修改过的电路及主要信号路径，处理影响阅读的问题。你不需要先学会描述布局参数，第一版之后仍可继续提出具体偏好。

## 顺着信号找到来源

`Ctrl+点击` 隧道、端口或导线，即可在当前子电路中查看上游驱动端、使用位置、分线器与总线位段映射。来源明确时直接跳转；有多个或不完整来源时显示候选。相关元件和导线会高亮，`Alt+←` 返回先前的位置。

这让隧道密集的译码和控制逻辑更容易阅读，也方便追查“这个字段从哪来”“这个控制信号送到哪里”。

## 一套真实课设的结果

内置 AI 已在 HUST 课设框架中实现并组织七个 CPU 入口，覆盖单周期、五段流水、气泡与前递、CCAB 2434 扩展指令以及多级中断。获得平台的实际错误反馈后，它继续修复逐拍行为和提交配置；选定路线的六份最终电路均经过新的平台自测，无错误输出。外层没有手改 CPU 实现。

这是包含人工反馈的完整实践，未提交正式平台评测。它说明这个工作台已经能用于真实复杂课设的构建和迭代；整套任务的一次性成功率与其他模型的效果，仍需更多实际使用来检验。

## 开始你的电路任务

下载下方对应系统的完整压缩包，解压运行。Windows 和 Linux x64 包都内置了所需运行环境；人工编辑与仿真无需连接 AI。AI 可使用你自己的 ChatGPT 登录，或支持流式 Responses API 的自定义接口。

把电路、任务书、组件库和测试程序放进同一个文件夹，直接告诉 AI：

> 按任务书完成这份课设，保留原面板和对外接口。验证关键功能，把电路按功能和数据流组织好，最后说明怎么运行及未验证的部分。

看到首版后，可以接着说：

> 主要数据流再清楚一些，缩短末端输出线；寄存器阵列的公共 CLK 保留直主干。修改后复查原来的功能。

复杂任务建议使用有较强推理、工具调用和图像理解能力的模型。本次课设使用自定义提供商的 `gpt-6-astra / high`。若有平台专用 ROM、向量地址或逐拍要求，一并提供；最后以你的课程环境实际运行结果为准。
